# 现代艺术 · 小小拍卖馆

基于 **GameFactory + Three.js r185** 的卡通风网页桌游，使用你提供的《Modern Art》PDF 标准规则。3–5 人房间联机，可添加机器人单人试玩。四轮拍卖、五种拍卖方式、市场结算、最终排名、重新开局均已实现。

## 本地试玩

需要 Node.js **22.12+**（推荐 Node 22 LTS）。在此目录运行：

```powershell
npm ci
npm run build
npm start
```

打开 **http://127.0.0.1:8787/**。可直接点击“和两位机器人试玩”，或填写昵称创建房间，将房间码分享给其他人。两个浏览器标签页拥有独立席位；刷新当前标签页会恢复同一席位。

已提供 `Start-Local.ps1`：安装缺失依赖、构建缺失网页包，然后启动服务。发布包自带 dist，可直接 `npm ci --omit=dev` 后 `npm start`。

局域网多人测试（同一 Wi-Fi）：

```powershell
$env:HOST = '0.0.0.0'
$env:PORT = '8787'
npm start
```

朋友访问 `http://你的局域网IP:8787/`。按操作系统提示允许此端口的专用网络访问。公网请在 Node 服务前使用 HTTPS 反向代理。

## 人机策略

人机逐一比较单张出牌、自配组合和结束本轮的方案，评估自己的藏品收益、对手受益、预期拍卖收入及跨轮留牌价值。第五张只参与排名、不计成交收益；本轮未进入前三的艺术家，其历史价值也不计入估价。有利时主动收轮，也会利用手牌扶持自己持有的冷门艺术家。

竞价按拍卖方式区分：公开拍卖以最低必要加价竞争，优先权拍卖考虑仅有一次出价机会，秘密拍卖折价报价，一口价保留无人购买时自购的余地。卖家自购会计算放弃对手付款的机会成本；早期保留部分周转现金。

市场预测采用 48 个确定性采样场景，仅使用本席位手牌、公共藏品、已出数量、历史行情和公开手牌张数，不读取对手现金、手牌或秘密出价。对手未来出牌及已弃牌分布使用近似估计，因此它是有风险折扣的启发式策略，并非完美信息搜索或保证最优的策略。

2026-10-28 验证：在 3／4／5 人局中各使用 4 副固定洗牌，并轮换新版人机的全部座位，对阵旧版追热门策略，共 48 局；新版获得 41 局胜利份额（并列按人数平分），最终现金平均高于同桌旧版人机约 129.7。此结果只衡量这批牌局对旧版的改善，不代表对真人的胜率。

## 部署

这是**前后端一体的 Node 服务**，需 WebSocket 与可写持久目录。单纯上传 dist 到静态托管无法联机。推荐 1 个 Node 实例、512 MB 内存起步；正式容量须按目标机器压测。

```sh
npm ci
npm run build
# Linux/macOS，公网监听由平台或反向代理配置
HOST=0.0.0.0 PORT=8787 DATA_DIR=/var/lib/modern-art node server/index.js
```

支持环境变量：

| 变量 | 默认 | 用途 |
|---|---|---|
| `HOST` | `127.0.0.1` | 服务监听地址，云平台设为 `0.0.0.0` |
| `PORT` | `8787` | HTTP 与 WebSocket 共用端口 |
| `DATA_DIR` | `.data` | 房间和重连凭证的持久目录，勿公开访问或提交 Git |
| `ALLOWED_ORIGIN` | 与请求 Host 相同 | 可显式指定唯一前端来源，例如 `https://art.example.com` |

`render.yaml` 已适配独立仓库根目录，包含持久磁盘配置。现有服务器部署工具见 `scripts/README.md`；拆仓不改变线上服务。其他 Node 平台使用同样的构建与启动命令即可。至少挂载一个持久卷，不能使用只提供临时文件系统的无状态实例。

Nginx 代理核心配置：

```nginx
location / {
    proxy_pass http://127.0.0.1:8787;
    proxy_http_version 1.1;
    proxy_set_header Host $http_host;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 90s;
}
```

TLS 证书和域名按自己的服务器配置。健康检查为 `/health`。请保持单实例：当前房间状态由单进程权威裁决；如需多副本，应先迁移到共享数据库和房间路由。

## 规则覆盖与明确差异

- 初始资金 100，70 张画，使用原版《现代艺术》的艺术家名称：Lite Metal 12、Yoko 13、Christin P. 14、Krypto 15、Karl Gitter 16。
- 正确按 3/4/5 人分发 10·6·6·0 / 9·4·4·0 / 8·3·3·0 张手牌；旧手牌保留。
- 公开、优先权、秘密、一口价、组合拍卖均由服务器验证。自己购买付银行，其他人购买付主持人。组合配牌者收取全部收入；下一主持人从其左手边开始。
- 第五张画触发结算但不成交；组合第四、第五张同时不成交。用完全桌手牌也立即结算，最后一张不成交。
- 行情板从左到右为黄、蓝、绿、红、橙，对应总牌数 12、13、14、15、16；本轮出牌数量平手时，左侧艺术家排名优先。只对本轮前三名兑现历史累积价值；其余类别本轮为 0。四轮后现金最高者获胜，同分共同获胜。
- **在线适配**：建房时可开关公开拍卖超时，并自定义 1–3600 秒（默认开启、15 秒），每次有效加价重置；关闭后等待其余玩家主动退出竞价，全部无人出价并退出则主持人免费获得。设置随房间保存，再来一局时保留；主动退出后本次不再加价。公开拍卖没有随机抢先权，其他方式按规则顺序执行。
- **PDF 缺失信息**：PDF 未提供各类别拍卖图标频率。本版使用 `catalog.js` 中明确列出的可编辑配比，不能当作已核对实体牌组的精确复制。
- 当前实现标准 3–5 人规则，**不含 PDF 中可选的三人虚拟玩家变体**。机器人是正常参赛者，使用与真人相同的信息视图。
- 画作为原创矢量插画；没有复制 PDF 原画、扫描页面或使用外部资源。

## 联机与存档

服务端是唯一规则裁决者，客户端不能决定成交、修改钱或看别人手牌。WebSocket 只发送 `publicView` 过滤后的状态；秘密出价在全员提交前只向本人显示。每个席位有随机 192 位凭证；凭证保存在浏览器 sessionStorage，不放进邀请链接。操作带版本号，过期操作会提示重新操作。

每个有效状态变化原子写入 `.data/rooms.json`。服务器重启后可以恢复，七天无活动的房间清理。保持存档目录私密。退出/关闭原标签页或清除浏览器会话存储后可能失去席位凭证；其他人无法冒领席位。断线玩家会保留席位，回合制选择等待其重连；不会偷偷换成机器人。房主离线时，在线玩家可“接任房主”。全员离线时机器人不继续；重新连接时已到期的公开拍卖会落槌。

## 性能

- Three.js 仅在画作、视角、尺寸改变时绘制；静止时无动画循环，后台停止绘制。
- 标准 DPR 最大 1.5，低功耗 DPR 1；无后处理、实时阴影或物理引擎。
- 场景约 **6,084 三角面 / 20 draw calls / 0 张 GPU 纹理**；画卡采用 SVG / DOM 绘制。
- 原创 SVG 卡面无需网络图片和字体。构建移除未使用的 Draco/Basis 解码器。
- 首屏 JS/CSS 压缩约 **180 KB**。预生成 gzip，服务端按浏览器支持自动发送；哈希资源长缓存，HTML 不缓存。
- WebSocket 仅在状态改变时同步，20 秒一次心跳；限制 4 KB 消息、单连接速率、200 房间/500 连接。容量上限是保护参数，不代表已验证的生产并发量。

## 开发与验证

```sh
npm run server  # 终端一：联机后端
npm run dev     # 终端二：Vite 界面，代理到 PORT（默认 8787）
npm test
npm run build
```

本项目已从 GameFactory 提取为独立 Git 仓库，安装、测试和构建直接使用上述 npm 命令，无需父仓库或 Python。`packages/a3game-playable` 随源码内置，游戏使用 `@a3game/playable` 根导出。初始提取来自原工作区的未提交游戏代码，来源见 `docs/Y-split-manifest.json`。

主要文件：

- `packages/modern-art/src/rules.js`：纯规则状态机与私密视图。
- `packages/modern-art/src/catalog.js`：70 张牌和拍卖配比。
- `packages/modern-art/src/art.js`、`gallery.js`：原创卡面和按需渲染的 GameFactory 3D 牌桌。
- `server/index.js`：WebSocket 房间、凭证、持久存储、静态服务、机器人调度。
- `src/main.js`、`src/table.css`：响应式中文界面。
- `packages/modern-art/tests`：规则、完整对局、联机、权限、重连与持久化测试。
- `VALIDATION.md`：实际验证记录和当前限制。

本实现是朋友间试玩的完整标准规则版本；未提供公共匹配、账户系统或付费功能。

## 仓库边界

`src/` 是界面，`server/` 是联机服务，`packages/modern-art/` 是规则和测试，`packages/a3game-playable/` 是随库框架，`scripts/` 是打包及部署工具。`VALIDATION.md` 等既有文档记录拆分前的开发验证；历史截图和发布包仍留在原 GameFactory 工作区。运行数据 `.data/` 不随源码迁移。
